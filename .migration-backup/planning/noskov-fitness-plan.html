One loop: program, perform, measure, adjust

Everything hangs off two clean libraries: movements and workouts. You place workouts on the calendar as the group's Rx version. Each athlete gets an automatic scaled copy with their own coaching notes. Their results feed back into the analysis and the engine's next suggestions.

Movements: one entry per movement, with variations underneath

Your BTWB history shows the duplicate problem clearly. It has about 1,480 different movement spellings, for example "Row Calories", "Row Calorie" and "Row (calories)". Basic cleanup brings that to about 580. The real number of movements is probably 150 to 200.

The fix is structural. A movement is the base pattern. A variation is a named child with fixed attributes: style, implement, assistance and standard. Typed names become aliases, so text in a workout always resolves to one entry. Adding a new movement first shows the closest existing matches.

Counts come from your file btwb_2026-11-22-workout_sessions.csv. The 150–200 figure is my estimate, to be confirmed when we review the list together.

Workouts: structured once, so they can be repeated and compared

A workout is a reusable record: a structure (for time, AMRAP, intervals, sets, EMOM, Tabata, skill practice) plus movements with reps, loads and Rx standards. A day holds one main workout. It can optionally start with a short practice part (lift technique or gymnastics skill). A heavy lift is the whole day.

The header tags are derived, not typed. Modality pattern, number of movements, load, volume, time domain and priority are worked out from the structure. You can override one when your judgment differs.

A workout marked ★ benchmark gets a retest interval. When one is due, the engine offers it for a day that fits.

The engine: rules you control, suggestions you approve

"Varied is not random": the engine looks at the gaps. It compares the last few weeks against your target mix on every dimension, then ranks candidate workouts by how much each one fills those gaps. Hard rules filter out anything unacceptable first. All targets and weights are settings you can edit, not code.

Group scaling: same workout, same clock, a different version for each person

The group does one Rx workout. Each person's version is time-matched: the engine knows each person's pace on a movement and sets reps so everyone spends roughly the same time on it. If someone's pace is too slow, the engine steps down the movement's scaling ladder.

reps = intended seconds × that person's pace, rounded. The pace is estimated from their recent results and updated after every workout.

Aggregate planning: the engine ranks gaps using the group's profile, so the shared workout targets shared weaknesses. Individual weaknesses get an optional 5–10 minute personal practice before the group workout. That way nobody's weakness gets lost in the average.

Fitness profile: our own, transparent method

Each category is scored 0–100 from that person's results, with the method visible. A category with no data shows "not measured", never "weak". Categories are similar to BTWB's: power lifts, Olympic lifts, speed, endurance, bodyweight, plus light, heavy and long metcons.

The group line is the average. The engine leans toward categories where the group line is low. Each person's lowest category drives their personal practice.

Sample values. Real levels need a reference scale. I suggest age- and sex-adjusted reference standards published in CrossFit sources and similar tables, never a fake population percentile.

Questions before I start building

  1. Weekly rhythm: fixed calendar days (for example Sunday rest), 3-on/1-off, or 5-on/2-off? Do all four of you train on the same days?
  2. Where and with what: a full gym (barbells, rings, rower, rope, GHD), a home setup, or both? Phase 1 is "all equipment", but I need each location's real equipment list.
  3. Sasha and Anton: ages, and roughly where each is now (for example, do they lift with a barbell, have pull-ups, double-unders)? This sets their starting scaling.
  4. Units: pounds everywhere, or kg for some people?
  5. Logging: does each person log on their own phone, or does one person log for the group after the workout? Both are possible.
  6. Your targets: starting mix, for example couplets+triplets 65%, single modality 20%, 4+ movements 15%; task 60% / time 40%. Should I propose defaults from your 2016–2025 history?
  7. Time domains: keep your sheet's definitions (short <4 min, medium 4–12, long 12–20, endurance 20–60)?
  8. Benchmarks: start with the Girls, Heroes, Open workouts and your Misc WODs tabs? Any you want retested on a fixed rhythm?
  9. Auto-programming depth: the engine proposes and you pick, or it fills a whole week that you then edit?
  10. Coaching notes: plain rule-based notes first, or written by an AI model from each person's history (more natural, small running cost)?
  11. Platform: are you comfortable with Claude Code + GitHub as the build home, hosting decided later?
  12. Other family history: do Olga or the kids have BTWB data to import too?
